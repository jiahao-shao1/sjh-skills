# team-digest

[English](README.md) | 中文

让团队通过各自的 agent 沟通。每个 agent 在自己的分支上提交详细的 commit，并用 issue 汇报，再由一份摘要汇总给团队。agent 只陈述发生了什么，由人来决定。

## 为什么要做

[session-team](../session-team/) 帮一个人管多个 session，这个 skill 是为了人与人之间的沟通。

逐个沟通很累，聊天也带不上全部 context。

比如某人的 agent 这周做了五件事。两件在本人擅长的领域，另外三件本人只提了需求。这件事本人未必想得到要说，agent 可以说出来，懂那个领域的队友也就能去看一眼。

## 它做什么

- **Commit：** agent 经常提交到团队仓库里自己的分支，message 写详细。推送前不需要人看，所以密钥和不该共享的内容不要放进去。
- **汇报：** agent 定期发一个 issue，方便大家对齐和讨论。其中说明做了什么，并附上仓库和 commit ID，方便别人找到确切版本。同时说明本人参与到什么程度（不清楚就写「未知」，不替本人声称看过）、验证到什么程度、验证的是哪个 commit、哪里没把握、想问谁。发布前由本人先看。
- **摘要：** agent 读完所有人的汇报，对照各人的分支，告诉团队谁做了什么、哪些事没人验证、谁说自己在等谁、哪里说法对不上、还有哪些问题没解决、哪些地方没能核对。摘要一屏内讲完，按会不会改变某人的决定排序；不影响决定的差异只写数量。它不给答案建议。

整个 skill 就是一份简短的说明文件，没有脚本，也不固定格式。agent 自己决定怎么写，并使用机器上现有的工具，所以每份记录的形式会有差异。

## 安装和上手

```bash
npx skills add jiahao-shao1/sjh-skills --skill team-digest
```

然后告诉你的 agent，比如：「把这些工作提交到 OWNER/REPO 里我的分支」「把我的团队汇报发到 OWNER/REPO 的 issue」或「根据 OWNER/REPO 写这周的团队摘要」。请使用私有仓库；只要 agent 能访问，其他共享位置也可以。

## 测试情况

这个 skill 还没有真实团队用过，也还没有用它产出过汇报或摘要。通过 `npx skills add` 安装同样没有测试过。
