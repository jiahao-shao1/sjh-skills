# team-digest

[English](README.md) | 中文

让团队通过各自的 agent 沟通，不写进度汇报。每个 agent 把做了什么提交到自己的分支；只有要对齐或决策的事才开主题 issue；有人想了解时才写摘要。agent 只陈述发生了什么，由人来决定。

## 为什么要做

[session-team](../session-team/) 帮一个人管多个 session，这个 skill 是为了人与人之间的沟通。

逐个沟通很累，聊天也带不上全部 context。

比如某人的 agent 这周做了五件事。两件在本人擅长的领域，另外三件本人只提了需求。这件事本人未必想得到要说，agent 可以说出来，懂那个领域的队友也就能去看一眼。

## 它做什么

- **Commit：** agent 提交并推送到团队仓库里自己的分支，message 只说干了什么。推送前不需要人看，所以密钥和不该共享的内容不要放进去。
- **主题 issue：** 只有要对齐或决策时才开，各方在 issue 下摆自己的做法。其中说明做了什么，并附上仓库和 commit ID，方便别人找到确切版本。同时说明本人参与到什么程度（不清楚就写「未知」，不替本人声称看过）、验证到什么程度、验证的是哪个 commit、哪里没把握、想问谁。只陈述，不反驳、不说服，发布前由本人先看。之后由人开会或点对点决定，agent 不做决定。
- **摘要：** 有人想知道别人在干什么时，agent 读对方的分支和相关 issue，告诉提问的人谁做了什么、哪里做法不同、还有哪些问题没解决、哪些地方没能核对。验证程度和本人参与程度，issue 里没写的就报「未知」。摘要一屏内讲完，按会不会改变某人的决定排序；不影响决定的差异只写数量。它不给答案建议。

整个 skill 就是一份简短的说明文件，没有脚本，也不固定格式。agent 自己决定怎么写，并使用机器上现有的工具，所以每份 issue 和摘要的形式会有差异。

## 安装和上手

```bash
npx skills add jiahao-shao1/sjh-skills --skill team-digest
```

然后告诉你的 agent，比如：「把这些工作提交到 OWNER/REPO 里我的分支」「在 OWNER/REPO 开个 issue 对齐这件事，摆一下我的做法」或「某人最近在 OWNER/REPO 干了什么」。请使用私有仓库；只要 agent 能访问，其他共享位置也可以。

## 测试情况

这个 skill 还没有真实团队用过，也还没有用它产出过主题 issue 或摘要。通过 `npx skills add` 安装同样没有测试过。
